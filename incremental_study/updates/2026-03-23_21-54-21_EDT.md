## Summary

A new standalone experimental harness was added under [incremental_study/](/Users/chris/Developer/school/csc490-v2/incremental_study). Its purpose is to study intrinsic verification similarity between an original model `M` and a perturbed model `M'` using independent from-scratch verification runs.

This work is intentionally separate from:
- [alpha-beta-CROWN/](/Users/chris/Developer/school/csc490-v2/alpha-beta-CROWN)
- [IVAN/](/Users/chris/Developer/school/csc490-v2/IVAN)

No proof transfer, template store, reused leaves, reused proof trees, branch reordering from prior runs, or cross-run caching was implemented.

## Backend Choice

The new harness uses `auto_LiRPA` as a thin backend through [verifier_adapter.py](/Users/chris/Developer/school/csc490-v2/incremental_study/verifier_adapter.py).

Reason:
- it avoids the Gurobi-heavy IVAN stack
- it gives direct access to root-stage bounds and ReLU instability information
- it can be called from external code without threading through the existing abcrown pipeline

## Implemented Workflow

The standalone workflow now does the following:

1. Load original model `M`.
2. Build perturbed model `M'`.
3. Load the same dataset-indexed robustness property set for both runs.
4. Verify `M` from scratch.
5. Verify `M'` from scratch.
6. Write structured JSON logs for both runs under a shared `pair_id`.

## Supported Model Paths

The harness currently supports:
- `.pt` / `.pth` checkpoints through a thin import-only use of IVAN's model registry
- `.onnx` models through `onnx` + `onnx2pytorch`

This keeps the new code self-contained while still letting it consume IVAN-sourced model assets.

## Supported Perturbations

Implemented perturbation modes:
- random weight noise
- symmetric quantization
- magnitude pruning

Each perturbed run also logs realized perturbation statistics, not just the requested perturbation spec.

## Logged Artifacts

### Run Metadata

- `run_id`
- `pair_id`
- `model_role`
- backend and verification method
- property ID and dataset index
- epsilon
- runtime
- final verification status

### Center-Input Behavior

- predicted label
- true-label match
- top-2 logit gap
- true-label logit
- constraint-margin summary

### Root Artifacts

- unstable ReLU count per layer
- total unstable ReLUs
- per-layer lower/upper bound summaries
- ReLU-layer pre-activation bound summaries
- root candidate split scores from LiRPA ReLU bound-improvement heuristics
- top-k root branch candidates with consistent layer/index identifiers

### Perturbation Realization

- overall relative L2 weight drift
- changed fraction
- zeroed fraction
- per-layer delta summaries
- perturbation-specific layer events

## Explicit Current Limitation

V1 is root-stage only. It does not expose a real branch-and-bound trace.

Because of that, the following requested artifacts are currently marked unavailable rather than approximated:
- split trace
- total nodes visited
- pruned nodes
- max depth
- first chosen splits in search order
- frontier evolution
- leaf count / tree size

This is deliberate. The harness does not fake BaB behavior when the backend does not expose it.

## Entry Point

The standalone entry point is:

```bash
python -m incremental_study.paired_runner ...
```

Example:

```bash
python -m incremental_study.paired_runner \
  --model-path /path/to/model.onnx \
  --dataset mnist \
  --eps 0.03 \
  --count 5 \
  --device cuda \
  --method CROWN-Optimized \
  --perturbation random_noise \
  --random-std 1e-3 \
  --random-relative \
  --output-dir incremental_study_runs
```

## Output Layout

Each run writes:

```text
incremental_study_runs/
  <pair_id>/
    pair_manifest.json
    original/
      <property_id>.json
    perturbed/
      <property_id>.json
```
